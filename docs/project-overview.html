Project Overview

Real-time fault monitoring and reporting for a simulated power-grid environment.

Purpose Fault Detection Real-Time Tasks System Flow Communication Methods Testing Modes

Application Purpose

This application was designed to demonstrate a real-time system that monitors and reports the condition of a simulated power grid, with specific attention given to fault events.

The simulation is implemented in Wokwi. A push button represents a power-grid fault and allows fault events to be introduced during testing. When the button is pressed, the system begins the fault-handling process.

Primary goal: Detect a simulated fault quickly, classify its condition, update the system indicator, and preserve the result in the system log.

Interrupt-Driven Fault Detection

The simulated fault button is configured as a hardware interrupt. This allows the system to respond immediately when a fault occurs rather than repeatedly checking the button through periodic polling.

An interrupt-driven design is valuable in a real-time system because the processor can continue performing normal tasks until an event requires immediate attention. Once the event occurs, the interrupt service routine records and signals the fault so the appropriate processing task can respond.

Real-Time Task Structure

The application uses four periodic tasks to simulate the major responsibilities of a power-grid fault-monitoring system. The tasks are ordered according to their real-time priority.

1

Fault Monitor

Detects and monitors incoming simulated fault events. This task has the highest priority because fault recognition is the most time-sensitive system function.

2

Fault Status Classification

Examines the recorded fault timestamp and assigns a classification that represents the detected system condition.

3

Update Fault Indicator

Updates the fault indicator according to the current classification and the simulated health of the power-grid system.

4

Power Grid Health Logging

Records the system condition, task activity, and fault information so the application maintains a history of its operation.

System Logic and Data Flow

The system begins by monitoring for a simulated fault event. Once the event is detected, its timestamp is recorded and passed through the classification process. The resulting classification determines how the fault indicator should represent the overall health of the system.

After the indicator is updated, the system condition and fault information are logged for monitoring and record-keeping purposes. This allows each stage of the fault response to be observed and tested.

Fault Event  →  Fault Monitoring  →  Status Classification  →  Indicator Update  →  Health Logging

ISR Communication Comparison

Another major feature of the application is the comparison between a binary semaphore and a direct task notification. Both mechanisms are used to signal a bottom-half task after the interrupt service routine detects a simulated fault.

Binary Semaphore

The binary semaphore provides a general synchronization mechanism that allows the interrupt service routine to signal a waiting task.

Direct Task Notification

The direct task notification sends the event directly to a specific task and is evaluated as a lower-overhead alternative for the fault-response path.

Measuring both methods makes it possible to determine which option provides the most effective response for this specific interrupt-driven application.

Idle and Loaded Testing

The application includes a configuration that allows the fault response to be tested with the four periodic tasks disabled or enabled.

No-Load Mode

The interrupt communication paths are measured while the processor has minimal competing work. This represents an ideal or peak-performance condition.

Loaded Mode

The four periodic application tasks are enabled while the interrupt paths are measured. This produces a more realistic test of the fault-monitoring system under active processor load.

Comparing these operating modes demonstrates how task priorities, processor load, and preemption influence the response time of the fault-handling system.

Overall Result

The completed application provides a functional demonstration of real-time fault monitoring for simulated power infrastructure. It combines interrupt-based event detection, prioritized periodic tasks, fault classification, condition indication, system logging, and communication-latency testing.

The design operates smoothly while offering multiple opportunities to test timing behavior, compare FreeRTOS communication methods, observe scheduling effects, and evaluate system performance under different processor loads.
